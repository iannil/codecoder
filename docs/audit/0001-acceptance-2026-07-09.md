## 3. 真实 LLM 端到端 — tool-loop 闭合(代理线级取证)

任务:「读 CONTEXT.md 并说出第一个标题」(`read_file` 为 `Permission::None`,无 Dialog 阻塞)。

- REQ1 `n_tools=25`,工具名与文档逐一致 → RESP1 `finish=tool_calls`
- REQ2 `roles=[user,assistant,tool]`,`TOOL_RESULT_MSG` 含 CONTEXT.md 真实磁盘内容 → RESP2 `finish=stop`,答案 `# CodeCoder`(正确)

结论:TUI 输入 → agent loop → 真实 LLM → tool_call → 真实磁盘读 → 结果回喂 → 二次 LLM → 正确答复。`tool_loop_executes_and_feeds_result_back` 以真实模型证实。

## 4. 权限门控 — 双向活体验证(真实模型)

任务:让 agent 调 `write_file`(`Permission::Ask{key:"write_file"}`, builtin.rs:150)。经代理捕获工具调用时机后应答 Dialog。

| 路径 | 应答 | 磁盘 | 回喂 tool result | 判定 |
|---|---|---|---|---|
| 批准 | Enter | 文件存在,内容 `GATE_OK` | `wrote 7 bytes to .gate_test_artifact.txt` | ✅ 放行→真执行→落盘 |
| 拒绝 | Esc | 文件不存在 | `permission denied by user` | ✅ 拦截→不执行→拒绝回喂 |

两次 `REQ=2`(loop 闭合)。门控**默认不放行**;拒绝转为 tool result 喂回模型,对话继续而非崩溃(符合 ADR 0019)。

## 5. 发现与处置

### 🔴 F1 — 开箱空身份(已修复)
代理显示首轮 `sys_len=0`、请求无 `system` 角色。溯源:`build_system_prompt`(agent.rs:580)从磁盘读 `AGENTS.md`,而该文件**未随仓库交付**(且非 gitignore),skills/capabilities/prompts 目录亦缺失 → 拼空串 → agent.rs:256 守卫跳过注入。后果:开箱运行时 agent **无身份注入**,违背架构头号原则「文件系统即自我 / AGENTS.md 自动注入 system prompt」。
**处置**:已在根目录补写最小 `AGENTS.md`(811 字节:身份 + 做事原则 + 指向 CONTEXT.md/ADR)。复验:同一黑盒链路 `sys_len` 由 `0 → 811`,`roles=[system,user,...]`,身份内容进入 system prompt 且跨 tool-loop 保持。机制本身正确,缺陷纯为文件缺失。

### 🟡 F2 — 配置模型不支持 tool-call(外部因素)
`CODECODER_MODEL=charaf/Huihui-Qwen3.6-...` 带 tools 请求时 Ollama 报 `invalid character '<'`(该模型先吐 `<think>`,tool-call 解析器失败)。纯聊天正常,但**任何需要工具的 agent 任务都会在 provider 层失败**。属模型/Ollama 兼容问题,非 CodeCoder 缺陷。
**建议**:改用 `qwen3:14b` 或 `qwen3-next:80b`(二者 tool-call 实测正常)。
