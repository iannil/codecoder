## 为什么现在做这个

`archived/pi` 这条轴 **ADR 0027 已系统梳理**(Wave 0 完成、Wave 1 #6 完成 #7 延后、
Wave 2 树状会话在途、Wave 3 机会性)。但 0027 **只看了 pi,从未分析 `archived/skills`**。

`archived/skills` 里其实有**两支**独立方法论:
- **engineer-\***(实现规划):**前向构造**——蓝图 CONTEXT.md → 里程碑 DAG → 执行。
- **rc-\***(RC = 观察收敛 / Observational Convergence,源自 zhurongshuo.com):**后向诊断/决策**
  ——把高维「可能性基底」沿方向收敛、锁定成一棵低维确定性的因果/根因树。

本文把 **skills(两支)、pi、codecoder 三体并置**,升一层做架构级审计:**三体各自把什么当
一等公民,交并之后 codecoder 的本体论缺了哪一块。** 不重复 0027 对 pi 的逐特征对照。

## 2. 三条哲学轴与它们的交并

**codecoder ∩ skills —— 同一条原则,不同的作用对象。**
codecoder 的「**文件系统即自我**」= skills 的「**状态即文件 / State Is Files**」,**同一条公理**。
但作用对象不同:codecoder 用在 **「agent 是谁」**(身份、skills、capabilities、memory、session
全落盘);skills 用在 **「agent 在做什么 / 在想什么」**(蓝图、里程碑、进度账本、**因果树**全落盘),
明确宣称「**即使整个对话上下文丢失,从这些文件也能完全恢复**」。

**engineer-\* ⟷ rc-\* —— 一对对偶。**
前者是**前向构造**(what to build:蓝图树*执行*出来);后者是**后向诊断/决策**(why broken /
哪根杠杆最高 / 哪步保留最多未来:假设树*生长*出来)。二者共用「树/图 + 节点」的形状,但方向相反、
判据不同。**这对对偶,正是本次修订的核心洞见**(详见 §4)。

**codecoder ⊥ pi —— 相反的边界哲学。** pi 刻意放弃权限/真隔离/子代理,codecoder 恰恰把它们
当一等公民(0027 已认定这是核心竞争力)。**这条不改。**

**skills ⊥ pi —— 重方法论 vs 极简。** codecoder 居中,且**已选定站位**:
> **机制在内核,方法在磁盘。**(来自 tree-sessions spec Phase E)树(数据结构)进内核当一等
> 公民;因果链/调试纪律写成 skill 用 `use_skill` 注入。

这条原则**直接约束了 rc 的落地形态**:rc 需要的**最小机制**(节点带验证状态/余量/杠杆)进内核,
**观察收敛的纪律**(逐节点、先验证后锁定、过早共识守卫)留 `skills/`。

## 3. 核心诊断:codecoder 缺的不是一棵树,是一对对偶双树

### codecoder 把「身份」文件化了,却把「工作」与「推理」都留在了草稿纸上。

**「单元」是什么——三体对照:**
- codecoder:单元 = 一个 **turn**。多步工作**无持久对象**;Background task 是**裸 `String`**
  (`background.rs:30`)。**推理过程完全不落盘**(review 产出自由文本即弃)。
- pi:同样 turn 本位;**刻意不要** plan/milestone,也无假设/根因模型。
- skills:**两个**持久单元——engineer 的**里程碑(DAG 节点)**、rc 的**因果节点(假设/锁定)**,
  都跨上下文重置存活。

**证据(codecoder 现状):**
- `plan`(`dev.rs:109`)= 一次性审批,**零持久物**;`todo`(`dev.rs:167`)= 扁平 `todos.json`,
  无依赖、无验收、不驱动调度。→ **前向构造无一等公民。**
- 没有任何结构表达「候选原因 / 假设 / 已排除 / 关键杠杆」。→ **后向诊断无一等公民。**
- Session 记录「发生了什么」(事后);**没有一等公民记录「打算做什么」(事前意图),也没有记录
  「为什么会这样」(诊断推理)。**

**三体交并暴露的空洞:** codecoder 的「文件系统即自我」覆盖了身份的每一层,**唯独漏了「工作」
与「推理」两层**——而这恰是 skills 两支的核心一等公民,也恰是 pi **主动放弃**因而无从借鉴的地方。

> 一句话:**Session 是「事后的树」。codecoder 还缺一棵「事前的图」(构造)和一棵「诊断的树」
> (推理)——而这三者其实是同一种「带验证状态的节点」结构。**

## 4. rc 理论(观察收敛)—— 被漏掉的对偶轴,与它能反ify 的原语

**RC ≠ 缩写**(rc-tutor 明令「RC 不是 Reflective Convergence,就是观察收敛」)。它是一套 7 公理
过程哲学;`rc-causal-chain` 是唯一把公理编译成**可执行推理算法**的技能,其余(advisor/tutor/
text-assistant/application-tool)是同一套公理的讲授/检索/透镜化。对 codecoder 有反ify 价值的是
causal-chain 的算法与其背后 3 条公理:

| 公理 | 落到 agent 的可反ify 原语 |
|---|---|
| **A3 观察锁定** | 未经校验的节点**不算事实**,标 `[假设]`;每加一个节点过**三项即时校验**(规范/直接且完备/无重复)才升为 `locked`。= agent 的「无证据不断言、假设显式化」纪律。 |
| **A6 过早共识守卫** | **反对一次性摊开整棵树**(=把一堆猜测互相印证成「客观现实」);逐节点展开,一次只深挖一条。= 反对 agent 一口气从猜测生成整张里程碑图/整套计划。 |
| **A7 余量守恒** | 每个节点带**可用余量 × 杠杆**;**关键节点 = 余量最大 × 杠杆最高**(常在汇聚节点);**末端二分**:真末端 `⊗自然律`(真无余量)vs 边界末端 `⊗边界`(余量在我权力边界外)。= 一个 margin×leverage 的**行动三选函数**。 |
| **可持续决策** | 选**保留最多余量、避免不可逆失败**的那步(「还能再来一轮」)。= 一个**可逆性判据**,独立于 cost/benefit。 |

**关键架构洞见:三棵结构共用一个「节点模型」。**
Session 的对话分支、Plan 的里程碑、rc 的因果节点,本质都是**带验证状态的节点**:

```
node := { id, parent/deps, status: locked | hypothesis, margin?, leverage?, terminal? }
```

这把 tree-sessions Phase E 已经起步的东西(把 `rc-causal-chain` 映射到会话树、节点带
`status: locked | hypothesis`)**一般化**:它不只是「debug 专用推理树」,而是 codecoder 所有
持久树/图共享的**最小节点机制**。rc 的**观察收敛纪律**(逐节点、先验证后锁定、余量×杠杆三选、
可逆性)则是一条 **skill**——完美落在「机制在内核、方法在磁盘」。

**对偶闭环:** rc 诊断树的产出(关键问题 / 高杠杆行动)可直接**喂给 Plan** 变成里程碑——
「为什么会这样」收敛出「接下来做什么」。诊断(后向)与构造(前向)在同一节点基底上首尾相接。

## 5. 一等公民候选(按架构中心度排序)

> 遵循「机制在内核、方法在磁盘」:内核只反ify 数据结构 + 调度/校验原语,方法论写 `skills/`。

### #1 —— 统一节点模型(带验证状态 × 余量 × 杠杆)—— 最深的地基

三体交并后**最深的公约数**。为持久树/图的节点定义统一形状:
`status: locked | hypothesis` · 可选 `margin` / `leverage` / `terminal(自然律|边界)`。
Session、Plan(#2)、因果树(#3)全部复用它。**最小、且是 #2/#3 的共同前提**;直接把
tree-sessions Phase E 的节点元数据从「debug 专用」提升为内核通用。

### #2 —— Plan:事前构造之图(engineer-\* 前向轴)

持久、带版本、可迁移(比照 Session / [[0004-session-persistence-and-migration]])的 **DAG**,
节点为里程碑:`title · acceptance(编码前先写的契约)· deps · status · owner · touched`。
- **驱动 loop:** 查询「下一个未阻塞节点」→ 派生清洁上下文子代理(阶段即子代理)→ 过验收(#4)。
- **↔ Background(0026):** 裸 `String` task 升级为「推进一张图」,外置调度器不再必需。
- **rc 纪律介入:** 生成里程碑时守 A6——不从猜测一次性摊开整图,逐节点锁定。
- **↔ Session:** 事前意图之图 vs 事后记录之树,节点 ↔ 会话分支可绑定。
- **命名待定(spec 决):** `plan`/`todo` 术语已占用,新公民需独立命名或显式重定义。

### #3 —— 推理/根因树:事后诊断之树(rc-\* 后向轴)

把 tree-sessions Phase E 的「推理/根因树」从 debug 专用**正式确立为一等公民**:复用会话树基底 +
#1 节点模型,承载 rc 的 `[假设]`/观察锁定、AND/OR、末端二分、关键节点。
- **机制在内核:** 树 + 节点元数据 + 「离开分支即摘要为何排除」(与 tree-sessions Phase C 配对)。
- **方法在磁盘:** `skills/rc-causal.md`——逐节点展开、三项即时校验、余量×杠杆三选、可持续决策。
- **产出回喂 #2**,构成诊断→构造的对偶闭环。

### #4 —— 验收裁决 + 架构偏移 rubric(扩展 `review`)

`review` 产出从自由文本升为**结构化裁决** `verdict ∈ {pass, needs_fix, rebuild}`,挂到 Plan
节点(与 #2 咬合)。rubric = engineer-inspector 三信号(篡改地基/过度设计/体积失控 + 术语漂移),
对 `git diff × CONTEXT.md/ADR` 比对。**tree-sessions 已列为独立快胜(:176),零架构改动,可最先落地。**

### #5 —— Blueprint:CONTEXT.md 从术语表升为「活蓝图」(一条 skill,做轻)

镜像纪律(蓝图与代码绝对镜像,只有验收通过的代码才更新蓝图)+ 漂移检测,写成 skill,不进二进制。
不引入 REQUIREMENTS.md→CONTEXT-MAP.md→FRONTEND-DESIGN.md 多文档棘轮。

### #6 —— 溯源统一(SourceInfo)

给每个 tool/skill/prompt/capability 挂统一 `SourceInfo`(路径/scope/origin),让「从哪来、
什么信任级」成为一等字段。[[0028-project-trust-load-gate]] 的自然延伸,小、防御性。

### #7 —— Hook / 拦截中间件(pi 未借的原语,暂缓)

pi 的 Extension Event Pipeline 可 `block`/`mutate`;codecoder 的 AgentEvent 仅出站。**张力:**
与自撰安全回路([[0022-self-authoring-safety-loop]])正面冲突(给了自撰物改写内核行为的口子)。
**低优先 + 需专门 ADR 论证边界,不建议近期做。**

## 6. 刻意不做一等公民(记理由,对齐 0027 风格)

- **engineer 技能梯 / rc 讲授层不进二进制。** engineer 的 job/orchestrator/workflow 编排、rc 的
  advisor/tutor/text-assistant 讲授,都是**方法论**,应活在 `skills/`,由 `use_skill` 注入。
  内核只提供 #1–#3 的节点/树机制。违反此界 = 从精简单二进制膨胀成工作流引擎。
- **pi 的 extension-as-everything 不采纳。** codecoder 刻意保四分 + Wasm/Docker 隔离。
- **实现规划的多文档棘轮 / rc 的哲学语料库不内核化。** 需要时写 skill。

## 7. 对在途工作的定位(避免踩踏)

- **tree-sessions(Wave 2)** 正把会话变树,**Phase E 已把「推理/根因树」起步为一等公民**
  (语义借 `rc-causal-chain`,并已定 `status: locked | hypothesis`)。**本文把它一般化**:
  Phase E 是 #1 节点模型 + #3 因果树的**第一块落地**;#2 Plan 是其前向对偶。三者互补不冲突。
- **inspector rubric 快胜**(:176)= 本文 #4,可并行独立落地。
- 本文**不改动 tree-sessions 任何 Phase**;新增项建立在 Session 持久化(0004)与压缩(0023)之上。

## 8. 综合结论

> **codecoder 已把「自我」文件化到了每一层——除了「工作」与「推理」两层。**
> skills 的两支从正反两向印证同一件事:把「文件系统即自我」施加于**一对对偶双树**——
> **Plan(事前构造之图)** 与 **因果/根因树(事后诊断之树)**,二者共享一个**带验证状态的
> 统一节点模型**,并在其上首尾相接(诊断收敛出构造)。pi 以「主动放弃 plan 与推理模型」从反面
> 印证了这一空洞。因此推荐的一等公民不是一个而是一族:**统一节点模型(地基)+ Plan(前向)
> + 推理树(后向)**,与既有的 Session(事后记录之树)合成 codecoder 完整的「文件化工作/推理」层。

**推荐落地次序(供评估,非承诺):**
1. **#4 验收 rubric**(零架构改动、独立快胜、tree-sessions 已备注)——先行练手「结构化裁决」。
2. **#1 统一节点模型**——随 tree-sessions Phase A/E 一并夯实(它本就要动节点元数据)。
3. **#3 推理树**(rc 纪律进 skill)——tree-sessions Phase E 的正式化。
4. **#2 Plan 工作图**(头号新增,较大,需 spec:数据模型 + 迁移 + 调度原语 + 命名裁决)。
5. **#5 Blueprint 镜像 / #6 溯源统一**(皆轻)。
6. **#7 拦截中间件**(暂缓)。

### 9.4 节点生命周期(统一节点模型 #1 的两种裁决)

```
构造侧(Plan):                         诊断侧(因果树):
 ┌─────────┐ deps done ┌────────────┐    ┌──────────┐ 三项校验 ┌────────┐
 │ pending │ ─────────▶│ in_progress│    │[假设]     │ ───────▶ │ locked │
 └─────────┘           └─────┬──────┘    │hypothesis│  通过     └────────┘
      ▲ 上游解除              │ 验收裁决   └────┬─────┘              │ A7 余量
 ┌─────────┐ 级联       ┌─────┴────┬───────┐   │ 未通过:留假设       ▼
 │ blocked │◀───────────needs_fix rebuild done  └─────────▶ 末端 ⊗自然律/⊗边界
 └─────────┘             │(回)    │(reset)             或 继续 grow
                          └─▶ in_progress ◀┘
```

**图注:** 四张图共同表达一个不变量——**「构造」(Plan/事前之图,前向)与「诊断」(因果树/
事后之树,后向)是一对对偶的一等公民,共享同一个「带验证状态 × 余量 × 杠杆」的统一节点模型,
并在其上首尾相接(诊断收敛出构造)。** 内核只提供节点/树机制与调度·校验·验收原语;rc 的
观察收敛纪律与 engineer 的编排方法论全部外置到 `skills/`。这补上了 codecoder「工作」与「推理」
两层的文件化空洞,又不违背「机制在内核、方法在磁盘」与自撰安全(0022)的既定边界。
